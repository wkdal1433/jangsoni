# 장손이(JANGSONI) 2.0 — 실행 및 후속 제작 안내

**원본 수달 비교안**은 원본 앉은 이미지를 첫 화면에 두고, 원본을 참조해 생성한 [서기·걷기 포즈 시트](assets/mascot/sprites/original-pose-atlas.png)를 둘러보기에 사용합니다. 아래 자산 준비·연결 안내는 기본 `v2` 프로토타입 기준입니다.

기준: 2026-11-04 / 제공 파일: `index.html` / 원본 캐릭터: `assets/mascot/original.png`

## 1. 실행

`index.html`을 Chrome, Edge 등 최신 브라우저에서 열면 됩니다. 외부 UI 라이브러리 없이 HTML, CSS, JavaScript로 동작하며, 기존 파일의 데이터·화면·조회 로직은 그대로 남겨두었습니다. 상품 약관 등 원래부터 인터넷을 필요로 하는 기능은 인터넷 연결과 해당 외부 서비스에 좌우됩니다.

## 2. 이번 프로토타입에서 완료한 범위

- 밝은 흰색·하늘색 기반의 Welcome, 역할 소개, 입력 방법, 7개 기능 안내, 예시 결과, 실제 입력 화면
- 원본 장손이 PNG 재사용, 미세한 눈 깜빡임, 느릿한 Hover 반응
- 7개 안내 카드의 단일 활성 상태, 역방향 스크롤 복원, 진행 표시, 카드별 기존 업무 화면 열기
- 기존 `#intro`, `#menu`, `#start`, `#case-form`, `#intro-yak`, `in-*` 요소와 `showScreen()` 및 `runAutoSearch()` 보존
- 모바일 배치, 키보드 포커스, 모션 감소 옵션

## 3. 아직 필요한 핵심 아트 자산

**실제 걷기 동작은 미완성입니다.** 원본 PNG는 앉은 자세 한 장이며, 이를 미끄러뜨리거나 흔들어 걸음처럼 속이지 않았습니다. 지금은 안내 구간에 원본 캐릭터가 정적으로 남아 있고 카드 포커스가 스크롤과 연동됩니다. 자연스러운 보행을 완성하려면 다음 투명 배경 PNG를 제작해야 합니다.

| 파일 | 내용 |
|---|---|
| `stand.png` | 서 있는 기본 자세 |
| `walk-01.png` | 왼발 접지 |
| `walk-02.png` | 왼발 통과 |
| `walk-03.png` | 중간 전환 |
| `walk-04.png` | 오른발 접지 |
| `walk-05.png` | 오른발 통과 |
| `walk-06.png` | 중간 전환 / 정지 직전 |

모든 이미지의 캔버스 크기와 캐릭터 기준 위치, 발이 닿는 바닥 높이를 맞추세요. 원본의 눈·안경·코·입·의상·로고·조명·질감을 동일하게 유지하고, 기존 노트북·돋보기·서류의 이동 방식을 먼저 결정하세요. 특히 생성형 이미지 모델은 프레임마다 얼굴과 브랜드 텍스트를 바꾸기 쉬우므로, **서 있는 정면 이미지 한 장을 원본과 비교해 확정한 다음** 그 이미지를 이용해 보행 프레임을 개별 생성·검수하는 편이 안전합니다.

이미지 제작은 GPT 이미지 생성이나 Gemini 이미지 생성 등으로 **원본 이미지를 참조하면서** 시도할 수 있습니다. 단순 텍스트만으로 새 수달을 만드는 것이 아니라 기존 원본 캐릭터의 포즈 변경을 요청해야 합니다. 프레임별 품질이 일정하지 않으면 Blender 또는 Photoshop/After Effects의 레이어 리깅 방식으로 마무리할 수 있습니다.

### 이미지 생성에 사용할 수 있는 기본 요청문

> 첨부한 장손이 원본 캐릭터를 그대로 유지하면서, 두 발로 서 있는 자세의 투명 배경 PNG를 만들어 주세요. 새로운 캐릭터로 재설계하지 마세요. 머리 윤곽, 밝은 하늘색 털과 질감, 은색 둥근 안경, 눈·코·입의 비율, 흰색·파란색 유니폼, AI CLAIM 로고, 꼬리, 조명 스타일을 원본에 맞추세요. 직립해 있지만 짧은 다리와 둥근 체형을 유지하고, 과도하게 사람 같은 비율은 사용하지 마세요. 정면에서 약간 측면을 보는 2.5D 자세로, 전신과 양발이 모두 보여야 합니다. 소품이 어떻게 처리되는지 자연스럽게 설명할 수 있도록 유지하세요. 그림자를 분리하기 쉬운 투명 배경으로 출력해 주세요. 그림 안에는 새 텍스트를 추가하지 마세요.

`stand.png`가 승인되면 각 걷기 프레임에서 **다리와 팔, 몸통 기울기만 소폭 바꾸고 나머지는 동일하게 고정**하도록 요청하세요. 자동으로 생성된 여러 프레임을 사용하기 전에 수동 검수가 필요합니다.

## 4. 보행 이미지 연결 방법

1. 위 이미지들을 `assets/mascot/sprites/`에 넣으세요.
2. `index.html`에서 `<script id="landing-script">` **바로 앞에** 아래 설정을 추가하세요.

```html
<script>
window.JANGSONI_STAND_FRAME = './assets/mascot/sprites/stand.png';
window.JANGSONI_WALK_FRAMES = [
  './assets/mascot/sprites/walk-01.png',
  './assets/mascot/sprites/walk-02.png',
  './assets/mascot/sprites/walk-03.png',
  './assets/mascot/sprites/walk-04.png',
  './assets/mascot/sprites/walk-05.png',
  './assets/mascot/sprites/walk-06.png'
];
</script>
```

실제 파일이 전부 로딩되면 스크롤 진행률에 맞춰 보행 프레임을 전환합니다. 없거나 로딩이 실패하면 원본 이미지로 안전하게 돌아갑니다. 모바일 모션 감소 설정에서는 걷기 프레임을 재생하지 않습니다.

## 5. 검증 범위와 주의점

Chromium 데스크톱(1440×900) 및 모바일(390×844)을 대상으로 렌더링, 기본 UI 동작을 확인했습니다. 7개 기능 카드에서 해당 업무 화면으로 진입, 첫 화면 복귀, 카드 1→2→4→7→3 역순 포커스 갱신, 모션 감소 옵션, 모바일 가로 넘침 검사에서 통과했습니다. 기존 애플리케이션의 각종 원격 보험·법률·의학 서비스 요청 결과, 개인정보 처리, 정확한 판정의 법적 타당성은 별도 검증 대상입니다.

**원본 업무 로직을 재작성하지 않았으므로** 바뀐 것은 주로 소개 UI/UX와 화면 스타일입니다. 실제 운영 전에는 서비스 연결 상태, 데이터 처리, 결과 표현과 모바일 실기기 동작을 추가로 점검하세요.
