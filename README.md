# 장손이(JANGSONI) 2.0 — 실행 및 후속 제작 안내

이 브랜치는 카드뉴스의 살구색·주황 테두리·노란 클립·짙은 회색 띠를 앱 화면에 적용한 비교안입니다. 테마는 `src/styles/hyundai.css`에서 관리하며, 기본 선택은 가이드 수달 이미지 묶음입니다.

가이드와 오리지널 비교안은 같은 화면·동작 코드를 사용합니다. 수달은 오른쪽 아래에 배치하고, 둘러보기 카드는 캐릭터 왼쪽에 둡니다. 두 이미지 묶음을 모두 포함하므로 설정한 경로를 바꿔 비교할 수 있습니다. 아래 자산 제작 메모는 초기 v2 기준입니다.

기준: 2026-11-04 / 제공 파일: `index.html` / 원본 캐릭터: `assets/mascot/original.png`

## 1. 실행

`index.html`을 Chrome, Edge 등 최신 브라우저에서 열면 됩니다. 외부 UI 라이브러리 없이 HTML, CSS, JavaScript로 동작하며, 기존 파일의 데이터·화면·조회 로직은 그대로 남겨두었습니다. 상품 약관 등 원래부터 인터넷을 필요로 하는 기능은 인터넷 연결과 해당 외부 서비스에 좌우됩니다.

## 소스 수정과 배포본 생성

`index.html`은 브라우저에서 바로 여는 배포본입니다. 개발할 때는 `src/`의 원본을 수정하세요.

- `src/page.html`과 `src/styles/`에서 화면과 스타일을 관리합니다.
- `src/analysis.js`와 `src/data/`는 기존 업무 기능과 내장 데이터를 담습니다.
- `src/ui/navigation.js`는 화면 이동과 브라우저 방문 기록을 관리합니다.
- `src/ui/journey.js`와 `src/ui/mascot.js`는 둘러보기 스크롤과 장손이 포즈 표시를 나눠 맡습니다.
- `src/ui/companion.js`는 업무 화면 오른쪽 아래의 장손이와 둘러보기에서 이어지는 이동을 담당합니다.
- `src/mascot-assets.json`의 `pack` 경로로 수달을 선택합니다. 가이드는 `assets/mascot/packs/guide/mascot.json`, 오리지널은 `assets/mascot/packs/original/mascot.json`입니다.
- 각 이미지 묶음의 `mascot.json`에서 이미지 경로·눈 위치·걷기 프레임 영역을 관리합니다. 가이드의 큰 시작화면 이미지는 원래 방향을 사용하고, `journey.flipX`와 `companion.flipX`로 걷기·작은 안내 수달만 좌우반전합니다. `scripts/mascot-assets.mjs`가 이 정보를 공통 화면과 동작에 연결합니다.

```sh
npm ci
npm run build
npm run build:check
```

`npm run build`로 생성한 `index.html`을 소스 변경과 함께 커밋하세요. `npm run build:check`는 생성 결과와 커밋 대상 파일이 일치하는지 검사합니다.

## 회귀 검증

이번 복구의 원인·비교 범위·실제 외부 연결 결과는 [전체 회귀 검증 보고서](docs/2026-11-05-full-regression.md)에 기록했습니다.

Google Chrome이 설치된 개발 환경에서 아래 검사를 실행할 수 있습니다. 테스트용 `playwright-core`와 `html2canvas`는 `npm ci`로 설치하며, 배포 HTML에 추가하지 않습니다. 각 검사는 독립된 브라우저 기록을 사용합니다.

```sh
npm run test:scroll
npm run test:regression
npm run test:companion
npm run test:mobile-mascot
npm run test:mobile-pointer
npm run test:mobile-devtools
npm run test:mobile-polish
npm run test:hero
npm run test:mobile-flow
```

- `test:scroll`: 둘러보기 열림/닫힘, 소개의 모든 섹션과 7개 카드의 정·역방향 전환, 빠른 휠 입력, 낮은 화면에서 긴 내용 읽기, 입력 중 일반 스크롤, 전환 중 화면 이동, 모바일 및 모션 감소 설정을 검사합니다.
- `test:regression`: 로컬 `main`의 원본 HTML과 업무 코드·압축 데이터를 대조합니다. 입력 항목, 판정·검색·탭·필터, 모든 카드뉴스 양식, 실제 PNG 생성, 편집 저장·복구·초기화, 뒤로가기와 둘러보기 직접 진입을 검사합니다. 이동 기록과 분석 준비를 위한 합의된 코드 차이만 별도로 정규화합니다.
- `test:companion`: 7개 메뉴의 첫 방문 안내, 확인·배경 클릭 후 완전 닫힘, 탭별 기록, 채팅·첨부·한글 조합 입력·임시 응답·깜빡임, 짧은/긴 드래그 복귀와 모바일 콘텐츠 여백을 검사합니다.
- `test:mobile-mascot`: 모바일의 고정 수달 영역·왼쪽 말풍선·7개 카드별 멘트·실제 걷기 프레임과 터치 이벤트로 탭/길게 누르기/손가락 따라가기/버둥거림/놓기/취소를 검사합니다.
- `test:mobile-pointer`: 실제 터치가 없는 PC 모바일 미리보기에서 마우스로 카드 본문·제목·태그·버튼을 끄는 동작, 취소/복구, 짧은 클릭, 기능 연결, 모션 감소 설정을 검사합니다.
- `test:mobile-devtools`: Chrome의 마우스→터치 변환을 켜고 카드 안을 천천히 끄는 경우를 검사합니다. 취소 불가능한 Touch Events가 들어와도 포인터 경로로 전환을 완료하고, 짧은 탭과 기능 연결을 유지하는지 확인합니다.
- `test:mobile-polish`: Chrome·WebKit에서 큰 섹션 6개, 데스크톱 소개 → 입력 안내의 한 번 전환, 모바일 소개의 맨 아래 → 다음 섹션 두 단계 이동, 도움말 영역 선택 방지와 일반 본문 선택, 장손이 터치·Lucide 아이콘·편집 문구 보존을 검사합니다. 처음 실행할 때 `npx playwright-core install webkit`으로 검사 브라우저를 준비하세요.
- `test:hero`: 1366×744를 포함한 첫 화면의 정·역방향 스냅, 원본 이미지·감은 눈의 표시 비율, 첫 깜빡임과 반복 간격을 확인합니다. 현대해상 브랜치에서는 승인된 `9fad8a0` 화면의 요소 위치·크기도 5개 화면 크기에서 대조합니다.
- `test:mobile-flow`: 전환 중 화면 높이가 바뀌는 경우를 Chrome·WebKit에서 검사합니다. Chrome에서는 실제 터치 이벤트·DevTools 마우스→터치 변환·휠의 세 입력으로 소개부터 입력 화면까지, 7개 카드와 역방향 경로를 위치 점프 없이 통과하는지 검사합니다. 실제 아이폰 실기기 검사를 대신하지는 않습니다.

자동검사는 프로젝트 HTML만 제공하는 임시 로컬 HTTP 서버에서 실행하고 종료 시 서버를 닫습니다. 모바일 미리보기 입력 문제의 재현·수정 범위는 [DevTools 입력 기록](docs/2026-11-06-devtools-input.md)을 참고하세요. 실제 휴대전화 실기기 검사는 별도입니다.

모바일 둘러보기와 잡기 동작의 변경은 [2026-11-06 작업 기록](docs/2026-11-06-mobile-mascot.md), 생성 이미지와 프롬프트는 [이미지 생성 기록](docs/2026-11-06-mascot-image-prompts.md)에 정리했습니다.

업무 비교 테스트는 외부 응답을 고정한 자료로 대체해 원본과 같은 조건에서 실행합니다. 실제 외부 서비스 연결 결과와는 구분합니다. 원본 비교에는 Git의 `main` 브랜치가 필요하며, 생성한 `index.html`이 소스와 맞지 않으면 검사를 시작하지 않습니다.

## UI 아이콘 규칙

사용자가 선택한 Lucide 1.70.0으로 UI 아이콘을 통일했습니다. `src/ui/icons.js`의 등록 목록에서만 이름을 추가하고 `data-icon`으로 사용합니다. 다른 아이콘 세트나 장식용 이모지를 UI에 섞지 않습니다. 사용자 입력·자료 문구와 회사 H 표시는 이 UI 아이콘 등록 대상에 포함하지 않습니다. 필요한 아이콘만 HTML에 묶으며 별도 아이콘 CDN 요청은 없습니다. Lucide의 배포 라이선스는 생성 HTML의 주석에 포함합니다.

## 3. 초기 v2의 아트 제작 참고

현재 비교안에는 걷기 시트가 포함되어 있습니다. 아래는 걷기 이미지가 없던 초기 v2의 제작 메모입니다. 원본 PNG는 앉은 자세 한 장이며, 이를 미끄러뜨리거나 흔들어 걸음처럼 속이지 않았습니다. 지금은 안내 구간에 원본 캐릭터가 정적으로 남아 있고 카드 포커스가 스크롤과 연동됩니다. 자연스러운 보행을 완성하려면 다음 투명 배경 PNG를 제작해야 합니다.

| 파일 | 내용 |
|---|---|
| `stand.png` | 서 있는 기본 자세 |
| `walk-01.png` | 왼발 접지 |
| `walk-02.png` | 왼발 통과 |
| `walk-03.png` | 중간 전환 |
| `walk-04.png` | 오른발 접지 |
| `walk-05.png` | 오른발 통과 |
| `walk-06.png` | 중간 전환 / 정지 직전 |

모든 이미지의 캔버스 크기와 캐릭터 기준 위치, 발이 닿는 바닥 높이를 맞추세요. 원본의 눈·안경·코·입·의상·로고·조명·질감을 동일하게 유지하고, 기존 노트북·돋보기·서류의 이동 방식을 먼저 결정하세요. 특히 생성형 이미지 모델은 프레임마다 얼굴과 브랜드 텍스트를 바꾸기 쉬우므로, **서 있는 정면 이미지 한 장을 원본과 비교해 확정한 다음** 그 이미지를 이용해 보행 프레임을 개별 생성·검수하는 편이 안전합니다.

이미지 제작은 GPT 이미지 생성이나 Gemini 이미지 생성 등으로 **원본 이미지를 참조하면서** 시도할 수 있습니다. 단순 텍스트만으로 새 수달을 만드는 것이 아니라 기존 원본 캐릭터의 포즈 변경을 요청해야 합니다. 프레임별 품질이 일정하지 않으면 Blender 또는 Photoshop/After Effects의 레이어 리깅 방식으로 마무리할 수 있습니다.

### 이미지 생성에 사용할 수 있는 기본 요청문

> 첨부한 장손이 원본 캐릭터를 그대로 유지하면서, 두 발로 서 있는 자세의 투명 배경 PNG를 만들어 주세요. 새로운 캐릭터로 재설계하지 마세요. 머리 윤곽, 밝은 하늘색 털과 질감, 은색 둥근 안경, 눈·코·입의 비율, 흰색·파란색 유니폼, AI CLAIM 로고, 꼬리, 조명 스타일을 원본에 맞추세요. 직립해 있지만 짧은 다리와 둥근 체형을 유지하고, 과도하게 사람 같은 비율은 사용하지 마세요. 정면에서 약간 측면을 보는 2.5D 자세로, 전신과 양발이 모두 보여야 합니다. 소품이 어떻게 처리되는지 자연스럽게 설명할 수 있도록 유지하세요. 그림자를 분리하기 쉬운 투명 배경으로 출력해 주세요. 그림 안에는 새 텍스트를 추가하지 마세요.

`stand.png`가 승인되면 각 걷기 프레임에서 **다리와 팔, 몸통 기울기만 소폭 바꾸고 나머지는 동일하게 고정**하도록 요청하세요. 자동으로 생성된 여러 프레임을 사용하기 전에 수동 검수가 필요합니다.

## 4. 보행 이미지 연결 방법

1. 위 이미지들을 `assets/mascot/sprites/`에 넣으세요.
2. `index.html`에서 `<script id="landing-script">` **바로 앞에** 아래 설정을 추가하세요.

```html
<script>
window.JANGSONI_STAND_FRAME = './assets/mascot/sprites/stand.png';
window.JANGSONI_WALK_FRAMES = [
  './assets/mascot/sprites/walk-01.png',
  './assets/mascot/sprites/walk-02.png',
  './assets/mascot/sprites/walk-03.png',
  './assets/mascot/sprites/walk-04.png',
  './assets/mascot/sprites/walk-05.png',
  './assets/mascot/sprites/walk-06.png'
];
</script>
```

실제 파일이 전부 로딩되면 스크롤 진행률에 맞춰 보행 프레임을 전환합니다. 없거나 로딩이 실패하면 원본 이미지로 안전하게 돌아갑니다. 모바일 모션 감소 설정에서는 걷기 프레임을 재생하지 않습니다.

## 5. 검증 범위와 주의점

Chromium 데스크톱(1440×900) 및 모바일(390×844)을 대상으로 렌더링, 기본 UI 동작을 확인했습니다. 7개 기능 카드에서 해당 업무 화면으로 진입, 첫 화면 복귀, 카드 1→2→4→7→3 역순 포커스 갱신, 모션 감소 옵션, 모바일 가로 넘침 검사에서 통과했습니다. 기존 애플리케이션의 각종 원격 보험·법률·의학 서비스 요청 결과, 개인정보 처리, 정확한 판정의 법적 타당성은 별도 검증 대상입니다.

**원본 업무 로직을 재작성하지 않았으므로** 바뀐 것은 주로 소개 UI/UX와 화면 스타일입니다. 실제 운영 전에는 서비스 연결 상태, 데이터 처리, 결과 표현과 모바일 실기기 동작을 추가로 점검하세요.
