## 브라우저에서 재현한 사실

- 1440×900에서 디자인 리뷰 전 `7ebae81`과 적용 후 `c1485aa`의 첫 화면 높이는 모두 850px이었다. 왼쪽 설명 영역의 세로 중심은 423px, 오른쪽 영역은 507px이었다.
- 현대해상 스타일 `2d8a822`에서는 첫 화면 높이 850px, 왼쪽 중심 433px, 오른쪽 중심 507px이었다.
- `773db08`, `7ebae81`, `c1485aa`, `b031685` 모두 첫 화면에서 315px 내린 상태에서 큰 수달과 작은 수달이 함께 보였다(1440×900).
- 둘러보기 끝에서 예시 섹션을 일부 보이게 내렸을 때에도 큰 수달과 작은 수달이 함께 보였다. 디자인 리뷰 전후 및 현대해상 스타일에서 재현했다.
- 1920×1080에서는 입력 섹션으로 이동해도 섹션 상단이 화면 상단에 맞지 않는 경우를 재현했다. 입력 섹션에 최소 화면 높이를 주고 상단 여백 설정을 제거한 뒤 정렬 검사를 통과했다.
- 둘러보기의 오리지널 수달은 카드 중앙에서 위쪽으로 치우쳐 있었다. `7ebae81`, `c1485aa`의 1440×900 검사에서 수달 영역은 약 173–586px, 활성 카드 영역은 약 254–646px이었다.

## 수정

- `src/styles/landing.css:22`: 첫 화면 최소 높이를 `100svh`로 맞춘다. 콘텐츠가 더 큰 작은 화면에서는 내용에 맞게 늘어난다.
- `src/styles/landing.css:29`: 양쪽 영역을 같은 세로 중심에 놓고, 캐릭터·캡션·말풍선을 오른쪽 영역 안에 순서대로 배치한다.
- `src/styles/landing.css:88`: 데스크톱 둘러보기 수달을 카드 중앙에 맞춘다. 말풍선·진행 표시는 캐릭터 아래에 배치하며, 낮은 화면에서는 그림 높이를 제한한다.
- `src/styles/landing.css:121`: 입력 섹션도 최소 `100svh`를 확보하고 이동 시 상단을 맞춘다.
- `src/styles/hyundai.css:30`(현대해상 브랜치): 카드 위쪽의 추가 20px 여백을 제거한다.
- `src/ui/companion.js:84`의 `update()`: 큰 시작화면과 둘러보기 섹션을 통과한 뒤 작은 수달을 표시한다. 업무 화면 진입과 기존 이동 애니메이션도 유지한다. 역방향으로 돌아가면 작은 수달을 숨긴다.

수정 커밋: 현대해상 `18c613a`, 가이드 `e493c5d`, 오리지널 `2b3ce03`.

## 검증

- 세 버전 × 10개 화면 크기 = 30개 조합을 검사했다: 1920×1080, 1440×900, 1366×768, 1280×720, 1024×768, 820×1180, 390×844, 1366×600, 721×540, 360×640.
- 모든 조합에서 첫 화면 진입 시 다음 섹션이 끼어들지 않았고, 말풍선이 첫 섹션 안에 있었으며 가로 넘침이 없었다.
- 첫 화면, 둘러보기 7개 카드, 끝 경계, 예시, 입력 섹션을 정방향·역방향으로 검사했다. 큰 수달과 작은 수달의 중복 표시가 없었다.
- 데스크톱 좌우 영역의 세로 중심 차이는 2px 미만이었다. 둘러보기 수달 중심과 화면 중앙의 차이는 검사 결과 최대 3px이었다.
- 빠른 휠 입력에서도 기존 900ms 걷기와 섹션 상단 전환이 동작했다. 모바일의 섹션 스냅과 모션 감소 설정도 통과했다.
- 세 버전의 짧은 드래그 380ms / 긴 드래그 300ms 복귀, 둘러보기에서 작은 수달로 이동, 브라우저 뒤로가기, 입력값 보존 검사를 통과했다.
- 변경 전 스냅샷과 입력 화면 6개·업무 화면 100개의 입력/편집 항목을 비교했다. 이름·타입·선택지·기본값, 사건 정보 전달, 타임라인 결과, 내장 조회 결과, 카드뉴스 텍스트, 의미별 상태 색상이 일치했다.
- `src/analysis.js`, `src/data/`, `src/page.html`, `src/ui/navigation.js`, `src/ui/journey.js`, `src/ui/companion-chat.js`, 마스코트 이미지 묶음은 이번 수정 전과 동일하다.
- 가이드와 오리지널의 공통 소스 차이는 `src/mascot-assets.json`의 선택 경로뿐이다.

검사는 독립된 Chromium 브라우저에서 수행했다. 외부 서비스의 실제 원격 응답과 모바일 실기기 동작은 이번 검증 범위에 포함하지 않았다. 브라우저 검사 스크립트와 전후 측정은 임시 작업 폴더의 `investigate-entry-layout.cjs`, `inspect-entry-tour.cjs`, `verify-entry-boundaries.cjs`, `entry-history/`에 저장했다. 입력·기능 검사는 `verify-field-parity.cjs`, `verify-pack-companion.cjs`, `verify-pack-sections.cjs`로 수행했다.

## 이후 디자인 변경 시 확인할 기준

색·글자·카드 크기를 바꿀 때 처음 진입한 화면만 확인하지 않고, 작은 높이의 창과 섹션 양쪽 경계도 검사한다. 큰 수달이 보이는 동안 작은 수달을 함께 표시하지 않으며, 입력 섹션 이동 후 상단 정렬과 뒤로가기 복원도 함께 확인한다.
