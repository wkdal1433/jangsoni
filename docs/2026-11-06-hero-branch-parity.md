# 첫 화면 전환의 브랜치 차이와 깜빡임 조정

## 사용자 요청과 이력 확인

사용자는 현대해상 버전의 스크롤 전환을 완성 기준으로 확정했고, 오리지널에서는 첫 화면을 벗어날 때 스냅이 안 되는 느낌을 보고했다. 현대해상 버전의 첫 화면 장손이는 첫 방문 중 깜빡임을 보기 어렵다며, 과하지 않은 범위에서 더 일찍 보이도록 요청했다.

조사 시작 시 현대해상은 `9fad8a0`, 가이드는 `2a92da2`, 오리지널은 `fa81b21`이었다. 오리지널에는 공통 UI 수정 `f933656`과 검증 기록 `fa81b21`이 반영돼 있었다. 당시 세 브랜치의 `src/ui`와 `src/styles/landing.css`는 동일했다. 따라서 최근 공통 스크롤 코드가 오리지널에서 누락된 상태는 아니었다.

직전 작업에서는 현대해상에서 전체 `test:scroll`을 실행했지만, 두 비교 브랜치에서는 `test:mobile-polish`·`test:companion`·`test:mobile-mascot`·`test:regression`만 실행했다. 기존 전체 스크롤 검사의 화면 높이도 600px·900px이었으며, 이번 차이가 나타난 744px 조건은 없었다.

## 수정 전 브라우저 재현

같은 로컬 HTTP 서버에서 각 Git 브랜치의 빌드 HTML을 열었다. Chrome 1366×744, 둘러보기 펼침, 첫 화면 맨 위에서 휠 90px을 한 번 입력하고 700ms 뒤의 좌표를 기록했다.

| 버전 | 첫 섹션 높이 | 첫 휠 후 스크롤 좌표 |
|---|---:|---:|
| 현대해상 | 744px | 744px |
| 가이드 | 744px | 744px |
| 오리지널 | 768.875px | 90px |

같은 폭에서 가이드의 큰 이미지 영역은 480px 높이, 오리지널은 518.875px 높이였다. 프로필의 첫 이미지 크기는 오리지널 864×934, 가이드 1254×1254다. 세로 이미지가 첫 섹션을 늘려 `onJourneyWheel()`의 긴 내용 읽기 조건에 들어갔고, 첫 휠에서는 일반 스크롤로 남았다. 기존 600px·900px 전체 검사는 수정 전 오리지널에서도 통과했으므로, 통과 결과만으로 이 중간 높이의 차이를 검증한 것은 아니었다.

## 수정 범위

- `src/styles/landing.css`: `.mascot-stage`를 1:1 표시 영역으로 고정하고, 이미지는 그 영역에 `object-fit:contain`으로 맞춘다. 사진 자체 비율과 감은 눈 SVG의 `xMidYMid meet` 정렬을 유지한다. 큰 사진이 세로라는 이유로 첫 섹션 높이가 늘어나지 않도록 한 변경이다. 참고: [MDN aspect-ratio](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/aspect-ratio), [MDN 이미지 비율 안내](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios).
- `src/ui/intro.js`: 첫 깜빡임은 화면에 보인 후 약 1,100ms에 시작하고, 이후 간격은 2,600~4,200ms로 설정한다.
- `src/ui/idle-motion.js`: 첫 실행 지연만 별도로 받을 수 있게 한다. 작은 장손이의 기존 호출에는 이 값을 전달하지 않으므로 기존 주기 설정을 사용한다. 탭 숨김·화면 이탈·모션 감소의 정지 조건과 145ms 단일 깜빡임·기존 두 번 깜빡임 동작은 유지한다.
- 스크롤 판정 코드·업무 분석 코드·데이터·입력 폼·이미지 파일은 이번 변경에서 수정하지 않는다.

## 검증 기준

`test:hero`는 1440×900·1366×744·1024×768에서 첫 화면이 화면 높이에 들어오는지, 둘러보기 열림/닫힘 각각 한 번의 휠로 정·역방향 전환이 되는지 검사한다. 눈 감은 이미지가 실제로 표시되는 시점, 첫 약 1.1초·다음 반복 간격·모션 감소 때 중지하는 동작도 확인한다.

현대해상 브랜치에서는 승인된 `9fad8a0` HTML과 현재 화면을 같은 조건으로 렌더링한다. 1440×900·1366×744·1024×768·390×844·320×568에서 첫 화면·캐릭터·소개·입력 안내·둘러보기·결과 예시·입력 화면의 위치와 크기를 0.1px 이내로 대조한다. 이미지와 깜빡임 레이어의 표시 영역은 별도로 확인한다.

## 실행 결과

수정 후 같은 1366×744·같은 휠 90px 조건에서 세 버전 모두 첫 섹션 높이는 744px, 첫 휠 후 좌표는 744px였다. 오리지널의 캐릭터 영역 높이는 480px로 맞춰졌다. 현대해상은 승인본 대비 5개 화면 크기에서 주요 요소의 위치·크기 대조를 모두 통과했다.

| 브랜치 / 구현 커밋 | 첫 화면·깜빡임 `test:hero` | 전체 경계 `test:scroll` | 추가 검사 |
|---|---|---|---|
| `v2-hyundai-style` / `fa72571` | 통과, 승인 레이아웃 5종 일치 | 통과 | `test:companion` 통과 |
| `v2-mascot-guide` / `aea4f66` | 통과 | 통과 | `test:mobile-polish` 통과 |
| `v2-mascot-original` / `be94f4a` | 통과 | 통과 | `test:companion`, `test:mobile-polish` 통과 |

가이드·오리지널의 공통 소스·검사·패키지 설정·README·docs 차이는 `src/mascot-assets.json`의 팩 경로뿐이다. 눈 감은 이미지와 원본 이미지 파일은 재생성하지 않았으며, 눈 레이어를 켠 오리지널 화면도 직접 확인했다. 이번 검사에 실제 휴대전화 실기기 검증은 포함하지 않는다.
