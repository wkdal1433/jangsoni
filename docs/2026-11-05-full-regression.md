# 스냅 누락 복구와 원본 업무 기능 대조

## 요청과 이전 검증의 누락

사용자는 특정 화면만 고치는 것이 아니라, 작업 과정에서 프로젝트가 손상된 부분을 찾아 복구하도록 요청했다. 이전 배치 검사와 부분적인 스냅 검사를 전체 검증으로 보고한 것은 검증 범위와 보고의 오류였다.

이전 `setupJourney()`는 둘러보기가 닫혀 있으면 휠 처리를 건너뛰었다. 전환 대상은 입력 방법 소개 → 둘러보기 제목 → 7개 카드 중앙 → 자료 정리 예시로 한정돼 있었다. 첫 화면, 역할 소개, 실제 사건 입력 섹션이 빠져 있었다. 모바일 스냅 대상도 입력 방법·둘러보기·자료 정리 예시 세 곳뿐이었다. 근거: 수정 전 `4192b66:src/ui/journey.js`, `4192b66:src/styles/landing.css`.

## 복구한 동작

- 소개의 모든 구간을 연결했다: 첫 화면 → 역할 소개 → 입력 방법 → 둘러보기 제목 → 7개 카드 → 자료 정리 예시 → 사건 정보 입력. 둘러보기가 닫혀 있으면 첫 화면과 사건 정보 입력을 연결한다.
- 섹션 이동 420ms와 카드 사이 걷기 900ms를 유지한다. 빠른 휠 입력으로 전환 중 목적지가 바뀌거나 여러 카드를 건너뛰지 않도록 한다.
- 화면보다 긴 설명은 끝부분까지 일반 스크롤로 읽은 다음 다음 섹션으로 전환한다. 입력칸·선택 상자·편집 중인 내용·채팅 위에서는 스냅이 입력을 방해하지 않는다.
- 전환 중 버튼 이동·뒤로가기·입력 포커스가 발생하면 진행 중 이동을 취소한다.
- 모바일은 소개의 여섯 섹션 모두에 브라우저 스냅을 적용한다. 입력 중 및 모션 감소 설정에서는 일반 스크롤을 유지한다.

구현: `src/ui/journey.js`의 `onJourneyWheel()`·`moveJourney()`, `src/styles/landing.css`의 모바일 스냅 설정. 이번 수정의 업무 화면·조회·판정 코드는 바꾸지 않았다.

수정 커밋: 오리지널 `82c468c`, 가이드 `044036a`, 현대해상 스타일 `5e214e3`.

## 원본 코드와 실제 결과 비교

`scripts/verify-business-regression.mjs`는 Git `main:index.html`을 독립된 임시 HTML로 열고, 현재 배포 HTML과 같은 조건으로 동작시킨다. 이번 비교 기준은 `549f2e1837d01f392cda7d40959d16d137667e32`이며, 로컬 `main`과 GitHub `origin/main`의 커밋 일치를 확인했다.

원본 업무 함수 80개와 이벤트 연결 36개를 포함하는 업무 코드 및 FSS·KCD 압축 데이터 두 묶음을 대조한다. 분석 준비를 공통 함수로 분리한 변경, 화면 이동을 방문 기록과 연결한 변경, 판례 iframe이 앱의 뒤로가기 기록을 늘리지 않도록 한 변경만 명시적으로 정규화한 뒤 전체 업무 코드가 일치하는지 검사한다. 검사 조건을 벗어나는 차이가 있으면 실패한다.

| 실제 조작한 범위 | 비교 및 확인 |
|---|---|
| 사건 입력 6개 + 업무 입력/편집 100개 | 이름·종류·선택지·기본값·값·활성 상태 일치 |
| 타임라인 6가지 조합 | 기본 입력, 예시, 직업 관련성·통지 여부, 면책기간, 계약 이전 진단의 결과와 카드뉴스 전달 일치 |
| 진료 이력 | 행 추가·수정·체크·삭제 |
| 약관 3개 분류 | 지급사유·제한사유 결과 일치 |
| 판례 8개 탭/필터 상태 | 내장 결과·조건 없는 결과·검색 결과·법제처 연결 주소 일치 |
| KCD 검색 4종 | 코드 2종·병명·없는 검색어의 결과 일치, 세 탭·모두 펼치기/접기·하위 코드 이동 |

| 검색 연결 | PubMed 검색 주소 및 원문 새 창 연결 |
| 이동 | 판례 갱신 후 뒤로/앞으로, 입력 수정 위치, 7개 둘러보기 직접 진입, 사건 정보 유지, 검색 예시 |

`scripts/verify-landing-scroll.mjs`는 높이 600px·900px에서 둘러보기 열림/닫힘을 각각 검사한다. 실제 휠 입력으로 모든 목적지를 순서대로 방문하고 역순으로 돌아오며, 전환 도중 큰 양·반대 방향 휠 입력도 보낸다. 모바일 여섯 섹션의 경계, 긴 내용 읽기, 입력 예외, 전환 취소 및 모션 감소 설정도 검사한다.

`scripts/verify-companion-regression.mjs`는 데스크톱·모바일에서 7개 메뉴 안내, 확인/배경 클릭 후 완전 닫힘, 같은 탭의 일반/강력 새로고침, 독립된 새 탭, 안내 다시 보기, 호버 그림, 말풍선 등장 애니메이션, 한글 조합 입력, 여러 첨부·첨부 제거, 초안 유지, 개발 중 응답, 자연 깜빡임과 모션 감소 설정을 검사한다. 데스크톱에서는 짧은 드래그의 균형 잡기·380ms 복귀, 긴 드래그의 어지러움·300ms 복귀와 드래그가 채팅을 열지 않는지도 확인한다. 메시지·첨부를 전송하는 외부 요청이 발생하지 않는지도 확인한다. 모바일에서는 7개 화면 모두 가로 넘침과 하단 수달 영역의 콘텐츠 가림을 검사한다.

실행 명령은 `npm run test:scroll`, `npm run test:regression`, `npm run test:companion`이다. 개발 환경에 Chrome이 필요하며, 생성 HTML과 소스 일치 검사도 포함한다. 배포 HTML은 계속 독립 실행 파일로 유지한다.

## 실제 외부 서비스 확인

고정 응답을 사용하는 업무 비교와 별도로 실제 공시실 연결을 확인했다. 원본과 현재 버전에서 상품명 `퍼펙트플러스종합보험`, 가입일 `2024-03-02`로 조회했다.

| 결과 | Git main 원본 | 현재 오리지널 |
|---|---:|---:|
| 조회된 상품 버전 | 3 | 3 |
| PDF에서 읽은 조항 | 286 | 286 |
| 선택 가능한 담보 | 271 | 271 |
| 목록에 없는 담보로 분석 시작 | 차단 | 차단 |
| 목록에 있는 담보로 분석 시작 | 메뉴 진입 | 메뉴 진입 |

공시실 검색·파일 위치 조회·PDF·PDF 읽기 라이브러리 응답은 모두 HTTP 200으로 관찰했다. 검사 원본은 임시 작업 폴더의 `probe-live-product.cjs`, `live-product-results.json`이다.

실제 연결 확인은 위 상품·가입일의 사례이다. 자동 업무 비교에서 PubMed 응답과 외부 사이트 화면은 고정 응답으로 대체하므로, 그 서비스의 모든 원격 데이터나 운영 상태까지 확인한 결과로 해석하지 않는다. 보험 판정의 법적 타당성은 이 회귀 검사의 대상이 아니다.

## 유지할 검증 기준

색·간격·모듈을 수정하더라도 화면이 열리는지만 확인하고 전체 검증이 끝났다고 보고하지 않는다. 원본과 달라진 코드 경로, 실제 조작한 상태, 정상 통과한 검사, 실제 외부 연결과 고정 응답의 차이를 구분해 기록한다. 승인된 디자인 변경은 유지하면서 회귀가 확인된 동작을 복구한다.
